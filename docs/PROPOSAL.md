## 2. Ключевая проблема: зависимости несовместимы в одном окружении

- `whisperx` → `torch~=2.8.0`
- `chatterbox-tts` → `torch==2.6.0`, `transformers==5.2.0`
- `coqui-tts` → `transformers>=4.57`; ROCm на Windows → собственная сборка torch

**Решение: «движки» в изолированных окружениях uv.** Каждый тяжёлый этап — отдельный
процесс-воркер со своим venv. uv хранит пакеты в общем кэше и линкует их, поэтому общий torch
не дублируется на диске. Плюсы:
- падение или OOM в движке не роняет приложение, а после выхода процесса VRAM освобождается **гарантированно**, а не на усмотрение `empty_cache()`;
- модель меняется одной строкой в конфиге (`tts.engine: xtts`), даже если ей нужен другой torch;
- тяжёлые слои (torch и CUDA) описаны в манифесте окружений и перекачиваются только при его изменении.

| Окружение | Состав |
|---|---|
| `core` (без torch) | Flet UI, очередь, yt-dlp, faster-whisper, CTranslate2 (MADLAD/NLLB), anthropic, keyring |
| `torch-main` (torch 2.8.x) | WhisperX-align, pyannote, Demucs/audio-separator, XTTS-v2, F5-TTS |
| `tts-chatterbox` (torch 2.6) | только если выберем Chatterbox |

Альтернатива — не брать пакет whisperx, а выровнять слова через `torchaudio.functional.forced_align`
(WhisperX делает примерно то же) и держать одно torch-окружение на свежем 2.15. Это проще, но
отходит от ТЗ, где WhisperX назван явно. **Рекомендую изоляцию движков.**

## 4. TTS: как выбираю модель

Сравнивать буду на этапе 2 **по измеримым метрикам** на одних и тех же 20 фразах с одним референсом:
- WER (переозвученное распознаём Whisper large-v3) — разборчивость и ударения;
- косинусное сходство спикеров (ECAPA) — похожесть голоса;
- RTF и пик VRAM — скорость и требования к железу;
- сэмплы для слепого прослушивания (A/B-страница). Естественность на слух оцениваешь ты: я звук не слышу.

Кандидаты: XTTS-v2 и F5-TTS-RU (по ТЗ) плюс Chatterbox-ML и CosyVoice3, у которых лицензия
позволяет коммерческое использование. Если коммерческое использование когда-нибудь понадобится,
у обоих кандидатов из ТЗ веса некоммерческие.

## 5. Профили (стартовые значения; уточняются бенчмарком)

| | Ультра ≥12 ГБ | Высокий 8–12 | Средний 6–8 | Низкий 4–6 | CPU |
|---|---|---|---|---|---|
| Whisper | large-v3, float16, batch 16 | large-v3-turbo, float16, 8 | large-v3-turbo, int8_float16, 4 | medium, int8_float16, 2 | small (medium при ≥8 ядрах и AVX2/AVX-512), int8, 1 |
| Demucs | htdemucs_ft, segment 7.8, shifts 2 | htdemucs_ft, 7.8, 1 | htdemucs, 7, 1 | htdemucs, 4, 0 | htdemucs, 7, 0 |
| TTS | выбранная модель, fp16 | fp16 | fp16 | облегчённая или fp16 | XTTS на CPU |
| Модели в памяти | ASR и TTS одновременно | по очереди | по очереди | по очереди | по очереди |
| Офлайн-перевод | MADLAD-3B int8_float16 GPU | то же | то же | MADLAD-3B int8 CPU | int8 CPU |
| Потоки CPU | физические ядра | то же | то же | то же | физические ядра − 1 |

- **yt-dlp `--concurrent-fragments`** зависит от замера сети, а не от GPU: 4 / 8 / 16 потоков при скорости < 20 / < 100 / ≥ 100 Мбит/с, aria2c `-x` так же.
- **Энкодер ffmpeg**: видео всегда идёт с `-c:v copy`. Энкодер (NVENC → QSV → AMF → libx264) нужен только в запасном пути, когда поток несовместим с контейнером, и для превью.
- **Понижение при OOM**: Ультра → Высокий → Средний → Низкий → CPU, повторяется только упавший этап.

## 6. Структура проекта

```
src/autodub/
  app/            Flet UI: экраны, тема, уведомления
  core/           конфиг (TOML + миграции), логи, очередь (SQLite), кэш этапов, IPC
  hardware/       detect/, profiles.py, calibrate.py, guard.py (проверки VRAM/RAM, понижение при OOM)
  pipeline/       stages/ (download, langid, separate, asr, diarize, translate, tts, fit, mix, mux)
                  engines/ (реализации, реестр по имени из конфига), runner.py
  components/     менеджер бинарников, моделей и окружений (SHA256, докачка, зеркала, «починить»)
  updater/        github.py (semver, каналы), apply.py, отдельный rollback-launcher
  cli.py          `autodub <url>`
installer/        Inno Setup .iss, launcher
scripts/          screenshots.py, release helpers
tests/            язык, тайминг, профили, semver, применение обновления
```

**Обновление без замены работающих файлов:** `app/versions/<x.y.z>/` + файл-указатель `current`.
Updater скачивает новую версию рядом, сверяет SHA256, переключает указатель и запускает её.
Если новая версия не прислала сигнал «стартовала» за N секунд, указатель возвращается на старую.
Бэкап получается бесплатно, а откат атомарный.

## 7. Лицензия приложения

**MIT.** Всё, что мы импортируем, совместимо с MIT: MIT, BSD, Apache-2.0, а MPL-2.0 у coqui-tts —
файловый copyleft, он действует только при изменении его файлов. GPL-бинарники (ffmpeg, aria2c)
запускаются как отдельные программы и скачиваются при первом запуске, а не линкуются. Веса
XTTS-v2, F5-TTS и NLLB **некоммерческие**: в README будет отдельный раздел и предупреждение
в настройках у этих моделей.

## 8. Чего не проверить в этом облачном контейнере

Контейнер Linux, без GPU и Windows. Здесь можно: CLI-пайплайн на CPU (если сеть пустит к
HF и YouTube), тесты, логику профилей и OOM-понижения на моках. **Нельзя:** CUDA/ROCm, NVENC,
реальный OOM, Inno Setup, Windows Credential Manager. Установщик и цикл обновления
v0.1.0 → v0.1.1 → откат прогоню в GitHub Actions на `windows-latest` (там нет GPU). Проверку
на GPU придётся сделать тебе: я подготовлю чек-лист и команду `autodub doctor --report`.
